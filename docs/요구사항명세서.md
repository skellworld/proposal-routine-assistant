# 제안서 작성 루틴 지원 로컬 웹사이트 — 요구사항 명세서 (v1.0)

작성일: 2026-10-29

## 1. 개요

### 1.1 목적
공공·민간 사업 제안서 작성 시 반복되는 루틴(RFP 분석 → 준비서류 확보 → 제안서 목차 구성)을
로컬 웹사이트에서 **파일 업로드 + 버튼 클릭**만으로 자동화한다. 분석·추출은 Claude API가 담당한다.

### 1.2 범위
| 단계 | 기능 | 산출물 |
|---|---|---|
| 1 | RFP 비교 분석 (금년 vs 전년도/과거 RFP) | 비교표(웹 표 + PNG 이미지), 요약 |
| 2 | 공고서 기반 제출서류 체크리스트 추출 | 체크리스트(별도 페이지에서 체크/저장) |
| 3 | 템플릿 선택 → RFP 목차 적용 PPTX 생성 | 목차가 반영된 .pptx 파일 |

### 1.3 사용 환경
- 실행: 서버 PC(`http://127.0.0.1:8000`) + Cloudflare Tunnel로 외부 https 주소 제공, 팀 다중 사용자(로그인)
- OS: Windows 11 (한글 폰트 `맑은 고딕` 사용)
- 런타임: Python 3.11+
- 외부 연동: 사용자별 Anthropic Claude API 또는 OpenAI(ChatGPT) API — 각자 본인 API 키 사용

### 1.4 계정·AI 연결 (서버화)
| ID | 요구사항 |
|---|---|
| FR-A-1 | 모든 화면·API는 로그인한 사용자만 쓸 수 있다(예외: 로그인·최초 설정·`/api/health`). 세션은 서명된 HttpOnly 쿠키(14일, 터널 경유 시 Secure)이며, 비밀번호를 바꾸면 기존 세션이 끊긴다. 로그인 실패는 IP당 10분에 10회로 제한한다. |
| FR-A-2 | 계정이 하나도 없으면 모든 접속을 `/setup`(관리자 계정 만들기)으로 보낸다. 최초 관리자 계정은 서버 PC에서 직접 접속한 경우에만 만들 수 있다(터널 경유 요청은 거부). |
| FR-A-3 | 관리자는 `/users`에서 팀원 계정을 만들고(임시 비밀번호 1회 표시), 비밀번호 초기화·역할 변경·삭제를 한다. 마지막 관리자는 삭제·강등할 수 없다. |
| FR-A-4 | 로그인 후 임시 비밀번호이거나 AI 연결이 없으면 다른 화면 대신 `/welcome`(시작하기)으로 보낸다: ① 비밀번호 변경 ② AI 연결(저장 후 연결 테스트 성공) ③ 시작. |
| FR-A-5 | `⚙ 내 AI 연결`(`/settings`)에서 사용자별로 AI를 고른다: Claude(Anthropic API 키) 또는 ChatGPT(OpenAI API 키). [키 확인]으로 키를 검증하고 그 키로 쓸 수 있는 모델 목록을 받아 고른다. 서버 PC에서 직접 접속한 경우에만 '이 PC의 Pro 계정(Claude Code)'도 고를 수 있다. |
| FR-A-6 | API 키는 서버 비밀키(`data/secret.key`)로 암호화해 `data/users.json`에 저장하고 화면에는 끝 4자리만 표시한다. 분석(백그라운드 작업 포함)은 그 작업을 시작한 사용자의 AI·키로 실행한다. |
| FR-A-5a | AI 선택지에 'AI 연결 안 함'이 있다. 고르면 최초 설정을 마친 것으로 보고, AI가 필요한 버튼(1단계 분석 실행, 2단계 공고서 분석, 추진 전략 다시 추천·자동 추천, 목차 추출, 템플릿 구조화·등록 시 구조화)을 끄고 본문 위에 'AI 연결하기' 안내를 표시한다. 서버도 해당 API(POST)를 400으로 거부한다. 업로드·결과 보기·체크리스트·목차 편집·PPT 생성은 그대로 쓸 수 있다. 화면에서는 AI가 필요한 요소에 `data-ai` 속성을 붙여 공통으로 처리한다. |
| FR-A-7 | 워크스페이스·템플릿·회사 현황은 팀 전체가 공유한다. 어떤 AI로 분석하든 결과는 서버의 워크스페이스에 저장된다. |
| FR-A-8 | '내 PC의 Claude Code' 방식: 사용자가 `⚙ 내 AI 연결`에서 실행기(`proposal-worker.py`, 표준 라이브러리 전용)를 내려받고 토큰을 발급해 자기 PC에서 실행한다. 실행기는 서버로 나가는 연결만 써서(`/api/worker/poll` long-poll, `/api/worker/result`) 그 사용자의 분석 작업을 받아 자기 PC의 Claude Code(구독 로그인)로 처리하고 결과를 돌려준다. 토큰은 해시로만 저장하고 재발급 시 이전 토큰은 무효. 실행기가 꺼져 있으면 분석 시 안내 메시지를 낸다. 설정 화면에 연결 상태(5초 간격)를 표시한다. |

## 2. 용어
- **프로젝트**: 하나의 입찰/제안 건. 업로드 파일·분석 결과·체크리스트·생성 PPT가 프로젝트 단위로 저장된다.
- **현재 RFP**: 이번에 제안할 사업의 제안요청서.
- **과거 RFP**: 비교 대상인 전년도 또는 과거 제안요청서 (1개 이상).
- **공고서**: 입찰공고문. 제출서류·자격요건·일정이 기재된 문서 (RFP 내에 포함될 수도 있음).
- **템플릿**: 제안서 디자인이 적용된 .pptx 파일.

| FR-T-3 | 자동 인식이 맞지 않으면 표지·간지·본문에 쓸 레이아웃을 사용자가 직접 지정할 수 있다. |
| FR-T-4 | [샘플 생성]으로 예시 목차를 적용한 PPT를 내려받아 템플릿 적합성을 미리 확인할 수 있다. |

### 3.1 단계 1 — RFP 비교 분석
| ID | 요구사항 |
|---|---|
| FR-01-1 | 현재 RFP · 현재 공고서 · 과거 RFP · 과거 공고서 4가지 분류로 각각 여러 파일을 업로드(드래그앤드롭/파일선택)할 수 있다. 현재 공고서는 단계 2와 같은 목록을 공유한다. |
| FR-01-1a | [한 번에 올리기] 영역에 여러 파일을 한꺼번에 놓으면 파일명으로 자동 분류한다('공고' 포함 → 공고서, 가장 최근 연도보다 이전이거나 '전년·과거' 포함 → 과거). 각 파일은 목록에서 분류를 변경할 수 있다. |
| FR-01-2 | [분석 실행] 버튼 클릭 시 Claude가 현재 문서 묶음(RFP+공고서)과 과거 문서 묶음을 비교 분석한다. 공고서가 있으면 참가자격·계약방식·공동수급·보증·제출방법·설명회 일정 항목을 추가하고, 항목별 근거 문서(RFP/공고서/공통)를 표시한다. RFP와 공고서 내용이 다르면 공고서를 기준으로 하고 불일치를 시사점에 적는다. |
| FR-01-3 | 비교 항목(기본): 사업명, 사업기간, 사업예산, 발주기관, 사업 목적/배경, 주요 과업범위, 기술/보안 요구사항, 투입인력 요건, 평가기준(기술:가격 비율 및 세부 배점), 제출서류, 제안서 분량/형식, 일정(공고·마감·발표), 기타 특이사항. 문서에 있는 항목은 Claude가 추가할 수 있다. |
| FR-01-4 | 각 항목은 `과거 / 현재 / 변경유형(신규·삭제·변경·동일) / 시사점` 열로 구성된다. |
| FR-01-5 | 결과는 웹 화면에 표로 표시하고, 변경유형별 색상 강조를 한다. |
| FR-01-6 | 동일한 비교표를 **PNG 이미지**로 렌더링하여 화면에 표시하고 다운로드할 수 있다. (한글 폰트 적용) |
| FR-01-7 | 종합 요약(핵심 변경점 3~5개, 제안 전략 시사점)을 함께 출력한다. |
| FR-01-8 | 분석 결과(JSON)는 저장되며, 재분석 시 덮어쓴다. |
| FR-01-9 | 과거 RFP 없이 현재 RFP만 올린 경우 단일 문서 요약 분석으로 동작한다(과거 열은 "-"). |
| FR-01-10 | 분석은 서버 백그라운드 작업으로 실행한다. 화면을 가리지 않고 진행 카드(경과 시간)를 표시하며, 다른 페이지로 이동하거나 다른 작업을 해도 계속된다. 1단계로 돌아오면 진행 상황을 이어서 보여 주고, 진행 중인 워크스페이스는 사이드바에 회전 표시가 붙는다. 다른 화면에 있을 때 분석이 끝나면 알림을 띄운다. 같은 워크스페이스의 분석은 동시에 하나만 실행한다(서버 재시작 시 진행 중 작업은 사라짐). |

### 3.2 단계 2 — 공고서 확인 및 준비서류 체크리스트
| ID | 요구사항 |
|---|---|
| FR-02-0 | 단계 1에서 '현재 공고서'가 있는 상태로 [분석 실행]을 하면, RFP 비교 분석과 공고서 분석·체크리스트 생성을 동시에 수행한다. 체크리스트 생성만 실패하면 비교 분석 결과는 저장하고 실패 사유를 표시한다. |
| FR-02-0a | 공고서 분석(공고번호·입찰방식·참가자격·공동수급·보증금·제출방법·일정·유의사항)과 준비서류 체크리스트는 단계 2 한 페이지(`/workspaces/<id>/step2`)에서 함께 조회·관리한다. 예전 체크리스트 주소는 이 페이지로 이동한다. |
| FR-02-1 | 공고서 파일을 업로드한다. 업로드하지 않으면 단계 1의 현재 RFP를 대상으로 한다. |
| FR-02-2 | [체크리스트 생성] 버튼 클릭 시 Claude가 실제 구비해야 할 문서/자료를 목록화한다. |

### 3.2-S 단계 3 — 핵심 추진 전략 추천 (단계 2와 목차 PPT 사이)
| ID | 요구사항 |
|---|---|

| FR-S-2 | 결과: 제안 콘셉트(슬로건)와 설명, 전략 5개(전략명, 거버닝 메시지, 근거·출처, 실행 방안 3개, 연계 평가항목·배점, 제안서 반영 위치), 놓치면 안 되는 리스크. |

| FR-S-5 | 왼쪽 바의 **회사 현황** 페이지(`/company`)에서 회사별(그룹사 / 컨소시엄 협력사) 소개를 자유 형식 텍스트(최대 30,000자)로 작성·수정·저장한다(`data/company.json`). 기본 그룹사로 시큐리티콘텐츠허브·시큐리티허브·한국정보보호교육센터를 두고, [+ 회사 추가]로 협력사를 추가·이름 변경·삭제할 수 있다. 예전 단일 현황은 시큐리티콘텐츠허브 현황으로 자동 이전한다. |
| FR-S-6 | 워크스페이스 **개요**의 '컨소시엄 구성'에서 이번 제안에 참여할 회사를 1개 이상 고르고 주관사를 지정한다(`project.companies`, 첫 번째 = 주관사, 미지정 시 첫 번째 회사). 추진 전략 추천은 선택한 회사들의 현황을 종합해 강점(회사명 명시)·보완점을 제시하고, 2개 이상이면 회사별 역할 분담(roles)을 함께 추천한다. 구성이나 현황이 바뀌면 3단계에 다시 추천 안내를 표시한다. |
| FR-S-6 | 회사 현황이 저장돼 있으면 전략 추천에 함께 넣어, 전략마다 근거가 되는 우리 강점(`our_edge`)을 표시하고, 요구사항 대비 부족한 점과 보완 방안(`gaps`)을 제시한다. 현황에 없는 실적·인력은 지어내지 않는다. 결과에 반영된 회사 현황 저장 시각을 기록해, 이후 현황이 바뀌면 [다시 추천]을 안내한다. |

## 6. 수용 기준 (Acceptance)
1. 현재/과거 RFP 업로드 후 [분석 실행] → 비교표(웹)와 PNG 이미지가 표시되고 다운로드된다.
2. 공고서 업로드 후 [체크리스트 생성] → 체크리스트 페이지에서 체크 후 새로고침해도 상태가 유지된다.
3. 템플릿 선택 후 [목차 추출] → 목차 편집 → [PPT 생성] → 다운로드한 PPTX를 PowerPoint로 열면 표지·목차·간지·본문 슬라이드가 템플릿 디자인으로 구성되어 있다.
