# 제안서 작성 루틴 지원 로컬 웹사이트 — 요구사항 명세서 (v1.0)

작성일: 2026-10-29

## 1. 개요

### 1.1 목적
공공·민간 사업 제안서 작성 시 반복되는 루틴(RFP 분석 → 준비서류 확보 → 제안서 목차 구성)을
로컬 웹사이트에서 **파일 업로드 + 버튼 클릭**만으로 자동화한다. 분석·추출은 Claude API가 담당한다.

### 1.2 범위
| 단계 | 기능 | 산출물 |
|---|---|---|
| 1 | RFP 비교 분석 (금년 vs 전년도/과거 RFP) | 비교표(웹 표 + PNG 이미지), 요약 |
| 2 | 공고서 기반 제출서류 체크리스트 추출 | 체크리스트(별도 페이지에서 체크/저장) |
| 3 | 템플릿 선택 → RFP 목차 적용 PPTX 생성 | 목차가 반영된 .pptx 파일 |

### 1.3 사용 환경
- 실행: 사용자 PC 로컬 (`http://127.0.0.1:8000`), 단일 사용자
- OS: Windows 11 (한글 폰트 `맑은 고딕` 사용)
- 런타임: Python 3.11+
- 외부 연동: Anthropic Claude API (`ANTHROPIC_API_KEY` 필요)

## 2. 용어
- **프로젝트**: 하나의 입찰/제안 건. 업로드 파일·분석 결과·체크리스트·생성 PPT가 프로젝트 단위로 저장된다.
- **현재 RFP**: 이번에 제안할 사업의 제안요청서.
- **과거 RFP**: 비교 대상인 전년도 또는 과거 제안요청서 (1개 이상).
- **공고서**: 입찰공고문. 제출서류·자격요건·일정이 기재된 문서 (RFP 내에 포함될 수도 있음).
- **템플릿**: 제안서 디자인이 적용된 .pptx 파일.

## 3. 기능 요구사항

### 3.0 공통 — 프로젝트 관리
| ID | 요구사항 |
|---|---|
| FR-00-1 | 제안 과업 하나를 **워크스페이스**로 관리한다. 워크스페이스는 이름·발주기관·제출 마감일·메모를 가진다. |
| FR-00-2 | 화면 왼쪽 **사이드바**에 워크스페이스 목록(마감 D-day, 단계 진행 표시)과 [+ 새 워크스페이스], [템플릿 관리] 메뉴를 항상 표시한다. 사이드바에서 워크스페이스를 선택하면 해당 워크스페이스로 전환된다. |
| FR-00-3 | 워크스페이스 안에서는 상단 탭(개요 / 1. RFP 분석 / 2. 공고서 / 체크리스트 / 3. 목차 PPT)으로 단계를 이동한다. |
| FR-00-4 | 워크스페이스 정보 수정, 삭제(확인 대화상자 필수)를 지원한다. 데이터는 `data/projects/<id>/project.json`에 저장되어 재실행 후에도 유지된다. |
| FR-00-5 | **새로고침 없는 화면 전환**: 메뉴 이동·버튼 동작 시 브라우저 전체 페이지를 다시 불러오지 않고, 사이드바와 본문 영역만 교체한다. 브라우저 뒤로/앞으로 가기와 주소(URL)는 정상 동작해야 한다. |
| FR-00-6 | 지원 업로드 형식: PDF, DOCX, HWPX, HWP, TXT/MD. 형식별 텍스트 추출기를 사용한다. |
| FR-00-7 | 텍스트 추출이 불가능한 PDF(스캔본)는 PDF 원본을 Claude에 문서 블록으로 직접 전달한다. |
| FR-00-8 | 홈(대시보드)에서 워크스페이스별 3단계 진행 상태와 마감일을 한눈에 보여준다. |

### 3.0-T 템플릿 관리
| ID | 요구사항 |
|---|---|
| FR-T-1 | 사이드바의 [템플릿 관리] 페이지에서 .pptx 템플릿을 업로드(드래그앤드롭)하고 이름·설명을 붙여 관리한다. |
| FR-T-1a | 업로드 시 설명을 비워두면 템플릿을 자동 분석(비율·테마 색상·글꼴·레이아웃·예시 슬라이드 텍스트)해 설명을 채운다. API 키가 있으면 Claude가 문장으로 작성하고, 없거나 실패하면 구조 기반 규칙으로 작성한다. |
| FR-T-1b | 설명은 언제든 사용자가 수정할 수 있고(수정 시 자동 저장), 출처(AI 분석 / 구조 분석 / 직접 입력)를 표시한다. [다시 분석]으로 새로 생성할 수 있으며, 직접 입력한 설명을 덮어쓸 때는 확인을 받는다. |
| FR-T-2 | 템플릿별로 슬라이드 크기(16:9 / 4:3), 레이아웃 목록, 자동 인식된 레이아웃 매핑(표지 / 간지 / 본문)을 보여준다. |
| FR-T-3 | 자동 인식이 맞지 않으면 표지·간지·본문에 쓸 레이아웃을 사용자가 직접 지정할 수 있다. |
| FR-T-4 | [샘플 생성]으로 예시 목차를 적용한 PPT를 내려받아 템플릿 적합성을 미리 확인할 수 있다. |
| FR-T-5 | 기본 템플릿 지정, 이름/설명 수정, 원본 다운로드, 삭제를 지원한다. 시스템 기본 템플릿은 삭제할 수 없다. |
| FR-T-6 | 단계 3에서는 템플릿 관리에 등록된 템플릿 목록에서 선택하여 사용한다(기본값: 기본 템플릿). |
| FR-T-7 | **양식 자동 구조화**: 업로드한 임의의 제안서 PPT(양식 또는 과거 제안서)를 Claude가 썸네일과 도형 구조로 분석해 표지·조견표·목차·간지·본문·뒷표지 대표 슬라이드를 고르고, 글자 자리를 `{{토큰}}`으로 바꾸고 예시 내용을 지운 **토큰형 양식 파일**로 변환한다. 업로드 시 선택(기본 켬) 또는 카드의 [양식으로 구조화]로 실행한다. |
| FR-T-8 | 구조화 결과로 역할별 미리보기 이미지, 사용 토큰, 요약, 확인할 점을 보여준다. 원본은 별도로 보관하며 [원본] 다운로드와 [다시 구조화](원본 기준)를 지원한다. |
| FR-T-9 | [양식 다운로드]로 토큰형 양식 파일을 받아 PowerPoint에서 디자인·토큰을 고친 뒤 다시 올릴 수 있다. 규칙: 슬라이드 노트 첫 줄 `#표지/#조견표/#목차/#간지/#본문/#본문-중/#뒷표지`, 토큰 `{{사업명}} {{세부사업명}} {{날짜}} {{목차번호}} {{목차제목}} {{대번호}} {{대제목}} {{중목차}} {{중번호}} {{중제목}} {{소번호}} {{소제목}} {{거버닝}} {{작성지침}}`. |

### 3.1 단계 1 — RFP 비교 분석
| ID | 요구사항 |
|---|---|
| FR-01-1 | 현재 RFP · 현재 공고서 · 과거 RFP · 과거 공고서 4가지 분류로 각각 여러 파일을 업로드(드래그앤드롭/파일선택)할 수 있다. 현재 공고서는 단계 2와 같은 목록을 공유한다. |
| FR-01-1a | [한 번에 올리기] 영역에 여러 파일을 한꺼번에 놓으면 파일명으로 자동 분류한다('공고' 포함 → 공고서, 가장 최근 연도보다 이전이거나 '전년·과거' 포함 → 과거). 각 파일은 목록에서 분류를 변경할 수 있다. |
| FR-01-2 | [분석 실행] 버튼 클릭 시 Claude가 현재 문서 묶음(RFP+공고서)과 과거 문서 묶음을 비교 분석한다. 공고서가 있으면 참가자격·계약방식·공동수급·보증·제출방법·설명회 일정 항목을 추가하고, 항목별 근거 문서(RFP/공고서/공통)를 표시한다. RFP와 공고서 내용이 다르면 공고서를 기준으로 하고 불일치를 시사점에 적는다. |
| FR-01-3 | 비교 항목(기본): 사업명, 사업기간, 사업예산, 발주기관, 사업 목적/배경, 주요 과업범위, 기술/보안 요구사항, 투입인력 요건, 평가기준(기술:가격 비율 및 세부 배점), 제출서류, 제안서 분량/형식, 일정(공고·마감·발표), 기타 특이사항. 문서에 있는 항목은 Claude가 추가할 수 있다. |
| FR-01-4 | 각 항목은 `과거 / 현재 / 변경유형(신규·삭제·변경·동일) / 시사점` 열로 구성된다. |
| FR-01-5 | 결과는 웹 화면에 표로 표시하고, 변경유형별 색상 강조를 한다. |
| FR-01-6 | 동일한 비교표를 **PNG 이미지**로 렌더링하여 화면에 표시하고 다운로드할 수 있다. (한글 폰트 적용) |
| FR-01-7 | 종합 요약(핵심 변경점 3~5개, 제안 전략 시사점)을 함께 출력한다. |
| FR-01-8 | 분석 결과(JSON)는 저장되며, 재분석 시 덮어쓴다. |
| FR-01-9 | 과거 RFP 없이 현재 RFP만 올린 경우 단일 문서 요약 분석으로 동작한다(과거 열은 "-"). |

### 3.2 단계 2 — 공고서 확인 및 준비서류 체크리스트
| ID | 요구사항 |
|---|---|
| FR-02-0 | 단계 1에서 '현재 공고서'가 있는 상태로 [분석 실행]을 하면, RFP 비교 분석과 공고서 분석·체크리스트 생성을 동시에 수행한다. 체크리스트 생성만 실패하면 비교 분석 결과는 저장하고 실패 사유를 표시한다. |
| FR-02-0a | 공고서 분석(공고번호·입찰방식·참가자격·공동수급·보증금·제출방법·일정·유의사항)과 준비서류 체크리스트는 단계 2 한 페이지(`/workspaces/<id>/step2`)에서 함께 조회·관리한다. 예전 체크리스트 주소는 이 페이지로 이동한다. |
| FR-02-1 | 공고서 파일을 업로드한다. 업로드하지 않으면 단계 1의 현재 RFP를 대상으로 한다. |
| FR-02-2 | [체크리스트 생성] 버튼 클릭 시 Claude가 실제 구비해야 할 문서/자료를 목록화한다. |
| FR-02-3 | 항목 속성: 분류(입찰참가·자격증빙·제안서류·가격서류·기타), 서류명, 상세설명/근거, 부수·형식(원본/사본/전자), 발급처, 필수여부, 근거 페이지/조항. |
| FR-02-4 | 공고서의 주요 일정(제출 마감, 설명회 등)도 함께 추출하여 상단에 표시한다. |
| FR-02-5 | 체크리스트는 공고서 분석과 같은 페이지에서 항목별 체크박스로 구비 여부를 표시한다. |
| FR-02-6 | 체크 상태와 메모는 즉시 서버에 저장되며 새로고침/재실행 후에도 유지된다. |
| FR-02-7 | 진행률(구비 n / 전체 m, %)을 표시한다. |
| FR-02-8 | 사용자가 항목을 직접 추가/삭제할 수 있다. |
| FR-02-9 | 체크리스트를 재생성할 경우 기존 체크 상태는 동일 서류명 기준으로 유지한다. |
| FR-02-10 | 체크리스트를 인쇄할 수 있다(인쇄용 스타일). |

### 3.2-S 단계 3 — 핵심 추진 전략 추천 (단계 2와 목차 PPT 사이)
| ID | 요구사항 |
|---|---|
| FR-S-1 | 단계 1 [분석 실행] 시 백그라운드에서 RFP·공고서(과거 문서 포함)를 근거로 이 사업의 핵심 추진 전략 5가지를 자동 추천한다. 사용자 입력은 필요 없다. |
| FR-S-2 | 결과: 제안 콘셉트(슬로건)와 설명, 전략 5개(전략명, 거버닝 메시지, 근거·출처, 실행 방안 3개, 연계 평가항목·배점, 제안서 반영 위치), 놓치면 안 되는 리스크. |
| FR-S-3 | 단계 3 페이지(`/workspaces/<id>/strategy`)를 열 때 결과가 없거나 생성 중이면 자동으로 받아오며(중복 생성 없음), 다른 화면으로 이동해도 생성은 계속된다. [다시 추천]으로 최신 1~2단계 분석을 반영해 재생성할 수 있다. |
| FR-S-4 | 현재 RFP·공고서에 평가 배점표가 있으면 전략 아래에 배점표(평가부문, 평가항목, 배점, 평가 기준, 기술:가격 비율, 합계, 근거 위치)를 문서 그대로 정리해 표시하고, 항목마다 이를 공략하는 추천 전략 번호를 연결한다. 배점표가 없으면 표시하지 않는다. |
| FR-S-5 | 왼쪽 바의 **우리 회사 현황** 페이지(`/company`)에서 회사 소개를 자유 형식 텍스트(최대 30,000자)로 작성·수정·저장한다(`data/company.json`). 모든 워크스페이스에 공통 적용된다. |
| FR-S-6 | 회사 현황이 저장돼 있으면 전략 추천에 함께 넣어, 전략마다 근거가 되는 우리 강점(`our_edge`)을 표시하고, 요구사항 대비 부족한 점과 보완 방안(`gaps`)을 제시한다. 현황에 없는 실적·인력은 지어내지 않는다. 결과에 반영된 회사 현황 저장 시각을 기록해, 이후 현황이 바뀌면 [다시 추천]을 안내한다. |

### 3.3 단계 4 — 템플릿 기반 목차 PPTX 생성
| ID | 요구사항 |
|---|---|
| FR-03-1 | 템플릿 관리에 등록된 템플릿을 카드(이름·설명·크기)로 보여주고 하나를 선택한다. |
| FR-03-2 | 새 템플릿 추가는 템플릿 관리 페이지에서 한다(단계 3에서 바로가기 제공). |
| FR-03-3 | 템플릿이 하나도 없을 때를 위해 기본 템플릿(기본 디자인)이 자동 생성된다. |
| FR-03-4 | [목차 추출] 버튼 클릭 시 Claude가 현재 RFP의 "제안서 작성 목차(작성요령)"를 계층 구조(대목차-중목차-소목차)로 추출한다. 각 항목에 작성 지침/배점 연계 메모를 포함한다. |
| FR-03-5 | 추출된 목차는 화면에서 수정(텍스트 편집, 추가, 삭제, 순서 이동)할 수 있다. |
| FR-03-6 | [PPT 생성] 클릭 시 선택한 템플릿의 슬라이드 레이아웃을 사용하여 다음 구조의 PPTX를 생성한다. ① 표지 ② 전체 목차 슬라이드 ③ 대목차별 간지(섹션) 슬라이드 ④ 중/소목차별 본문 슬라이드(제목 + 작성 지침을 발표자 노트에 기재). |
| FR-03-7 | 템플릿 레이아웃은 템플릿 관리에서 지정한 매핑을 우선 사용하고, 없으면 이름/플레이스홀더 유형으로 자동 매핑한다(Title / Section Header / Title and Content). 매핑 실패 시 첫 레이아웃으로 대체한다. |
| FR-03-8 | 템플릿에 원래 포함된 예시 슬라이드는 생성 결과에서 제거한다(디자인·마스터는 유지). |
| FR-03-9 | 생성된 파일은 `data/projects/<id>/output/`에 저장되고 다운로드 링크를 제공한다. |

## 4. 비기능 요구사항

## 5. 시스템 구성

```
브라우저 (HTML/JS, 서버 렌더링 Jinja2)
   │  HTTP (127.0.0.1:8000)
FastAPI 서버 (app/main.py)
   ├─ extractors.py   : PDF/DOCX/HWPX/HWP/TXT 텍스트 추출
   ├─ claude_client.py: Claude API 호출(구조화 출력)
   ├─ analysis.py     : 단계1 비교분석, 단계2 체크리스트, 단계3 목차 추출 프롬프트/스키마
   ├─ table_image.py  : 비교표 → PNG (matplotlib, 맑은 고딕)
   ├─ pptx_builder.py : 템플릿 + 목차 → PPTX (python-pptx)
   └─ storage.py      : 프로젝트 JSON/파일 저장
data/
   ├─ projects/<id>/{uploads, output, project.json}
   └─ templates/*.pptx
```

### 5.1 주요 화면
| 경로 | 화면 |
|---|---|
모든 화면은 `왼쪽 사이드바 + 본문` 프레임 구조이며, 화면 전환 시 본문(과 사이드바)만 교체된다.

| 경로 | 화면 |
|---|---|
| `/` | 홈(대시보드): 워크스페이스 현황 |
| `/templates` | 템플릿 관리 |
| `/workspaces/<id>` | 워크스페이스 개요: 정보 수정, 3단계 진행 상태 |
| `/workspaces/<id>/step1` | RFP 비교 분석 |
| `/workspaces/<id>/step2` | 공고서 분석·체크리스트 생성 |
| `/workspaces/<id>/checklist` | 체크리스트(체크 전용 페이지) |
| `/workspaces/<id>/step3` | 템플릿 선택·목차 편집·PPT 생성 |

### 5.2 주요 API
| Method | Path | 설명 |
|---|---|---|
| POST | `/api/projects` | 워크스페이스 생성 |
| PUT | `/api/projects/{id}` | 워크스페이스 정보 수정(이름·발주기관·마감일·메모) |
| DELETE | `/api/projects/{id}` | 워크스페이스 삭제 |
| POST | `/api/projects/{id}/files/{kind}` | 파일 업로드 (kind: current_rfp, past_rfp, notice) |
| DELETE | `/api/projects/{id}/files/{kind}/{name}` | 업로드 파일 삭제 |
| POST | `/api/projects/{id}/step1/analyze` | 비교 분석 실행 |
| GET | `/api/projects/{id}/step1/table.png` | 비교표 이미지 |
| POST | `/api/projects/{id}/step2/generate` | 체크리스트 생성 |
| PUT | `/api/projects/{id}/checklist` | 체크리스트 저장(체크/메모/추가/삭제) |
| GET/POST | `/api/templates` | 템플릿 목록(메타데이터 포함)/업로드 |
| PUT/DELETE | `/api/templates/{file}` | 이름·설명·레이아웃 매핑·기본 지정 수정 / 삭제 |
| GET | `/api/templates/{file}/download` | 템플릿 원본 다운로드 |
| POST | `/api/templates/{file}/sample` | 예시 목차로 샘플 PPT 생성 |
| POST | `/api/projects/{id}/step3/toc` | 목차 추출 |
| PUT | `/api/projects/{id}/step3/toc` | 목차 수정 저장 |
| POST | `/api/projects/{id}/step3/build` | PPTX 생성 |
| GET | `/api/projects/{id}/output/{file}` | 결과물 다운로드 |

## 6. 수용 기준 (Acceptance)
1. 현재/과거 RFP 업로드 후 [분석 실행] → 비교표(웹)와 PNG 이미지가 표시되고 다운로드된다.
2. 공고서 업로드 후 [체크리스트 생성] → 체크리스트 페이지에서 체크 후 새로고침해도 상태가 유지된다.
3. 템플릿 선택 후 [목차 추출] → 목차 편집 → [PPT 생성] → 다운로드한 PPTX를 PowerPoint로 열면 표지·목차·간지·본문 슬라이드가 템플릿 디자인으로 구성되어 있다.
